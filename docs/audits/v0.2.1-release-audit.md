## 3. Fixes and their verification

### R-1: a dialog closing inside another closed its parent

- **Cause:** `<dialog>` `close` and `cancel` events do not bubble in the DOM, but React passes them up the component tree to the `onClose`/`onCancel` of the dialogs around it. When the re-auth dialog (rendered inside the webhook dialog) closed, the webhook dialog's `onClose` fired as well.
- **Fix** (`client/packages/client/src/design/ui.tsx`): `Dialog` reacts only to its own `close` and `cancel` events (`event.target === ref.current`). This covers every nested dialog, including Escape on a confirmation inside another dialog.
- **Verification:**
  - Unit: `design/dialog.test.tsx` "closes alone". It fails on v0.2.0 code (outer `onClose` called once) and passes with the fix.
  - E2E: `release-flows.spec.ts` webhook test. The first create is answered `403 reauth_required` (as the server does once the sign-in is older than `PENFII_REAUTH_WINDOW_SECONDS`), then the real re-auth and retry follow. It fails on the v0.2.0 web image in all three engines (the secret is never shown) and passes on v0.2.1 in all three.
  - Manual: the same flow by hand on the stack.

### R-2: webhook revoke and rotate ask first

- **Fix** (`modules/conversations/ChannelWebhooks.tsx`, en/ko messages): a confirmation through the shared `useConfirm` before `revokeWebhook` and `rotateWebhook`. The wording says the current secret stops at once.
- **Verification:**
  - Unit: `ChannelWebhooks.test.tsx` checks that Cancel revokes nothing, and that confirming revokes or rotates.
  - E2E: the webhook test covers Cancel, Revoke, and a post with the revoked secret, which gets `401`. It passes in three engines.

### R-3: floating menu clamp

- **Cause:** `floatingMenuPosition` clamped only the edge on the side it opened toward. With the trigger below the window, the menu opened upward from the trigger and its bottom ran past the window.
- **Fix** (`shell/nav/floatingMenuPosition.ts`): the top is clamped so that the whole (height-limited) menu is inside the viewport on both sides.
- **Verification:**
  - First seen in the existing `channel-ticket-ux` "viewport edge" test, which failed in Chromium and Firefox on the first run. That test depends on the sidebar's length.
  - Made deterministic in `release-flows.spec.ts` "a floating menu whose trigger leaves the viewport": the trigger is put low in a tall window, the window shrinks below it, and the menu must stay inside. It fails on the v0.2.0 web image in all three engines and passes on v0.2.1.
  - Unit: `floatingMenuPosition.test.ts` adds the trigger-below and trigger-above cases.

### MU-1: the first `project.ready` reads open Tickets again

- **Fix** (`modules/work/projectSync.ts`, `refresh.ts`): on the first `project.ready` the client also marks stale every Ticket of that Project in its cache, with its comments, files, children, history and dependencies (`refreshProjectTickets`). Only queries on screen are read again, and only Tickets of that Project. A later connection still continues from its position, without a whole read.
- **Verification:**
  - Unit: `projectSync.test.ts`.
  - E2E: `multi-user.spec.ts` "an open ticket catches up…", whose `test.fail` is removed. The Project socket is held with `routeWebSocket` while the owner renames the ticket. The panel now shows the new title. Passed in all 8 multi-user runs.

### MU-2: losing a Project tells the person even without a channel row

- **Fix** (`server/crates/core`):
  - `LostParticipation::notices(others)` sends `Access` and `Space` notices to everyone who lost a membership, and also to everyone the change may have taken out of the Project. That is the person whose direct role was removed (`remove_grant`) or who was removed from a Team (`admin::remove_team_member`), and the Team's members when a Team is unlinked or its participation ends.
  - `Access` closes their sockets. The client's reconnect then reads the Space again, so the channel leaves the sidebar and the page shows that they no longer have access.
  - Telling someone who is still in costs one Space read and one reconnect.
- **Verification:**
  - Integration test `board_realtime::losing_the_project_tells_someone_who_held_no_channel_membership`. A user socket stays open across the removal of a direct role; after it, a notice is published that an open socket would pass on. The test fails on v0.2.0 code (the socket delivers that `inbox.changed`) and passes with the fix. A Project socket opened again is refused.
  - Integration test `board_realtime::losing_the_project_through_its_team_tells_the_teams_people` (added in the release review). It covers the Team's three ways out, one after another: participation ended, link removed, left the Team. It fails on v0.2.0 code at the first one and passes with the fix.
  - E2E: `multi-user.spec.ts` test 12 now requires the page to change without a reload. "You are not part of this project." or Not found shows, the composer is gone, and the channel has left the sidebar, in 0.8–1.4 s in all 8 v0.2.1 runs (WebKit and Firefox).

### MU-3: private channel header

- **Fix** (`pages/SpacePage.tsx`): for a private Project channel the header uses the channel's members (`/v1/channels/{id}/members`, which every reader of the channel may list). Public Project channels still show the Project's members, since everyone in the Project reads them.
- **Verification:**
  - Unit: `pages/conversationHeader.test.tsx`. It fails on v0.2.0 code and passes with the fix.
  - E2E: `multi-user.spec.ts` test 13, whose `test.fail` is removed. It shows "Private · 1 members" for one channel member in all 8 runs.

### MU-4: why nothing was changed

The v0.2.0 journals and the v0.2.1 runs show the same order of events:

1. The page loads.
2. The user socket starts its first handshake.
3. Sign-out is pressed about 230 ms later.
4. The session is gone before the handshake reaches the server, which answers `401`.
5. Firefox logs the refused handshake.

The two changes tried, in that order, were these:

- Stop every socket before the sign-out request.
- Close a still-connecting socket only once it has opened.

Neither can stop a handshake that is already on its way, and neither changed anything in the existing suites, so both were reverted. A person signs out from a settled page. The test now waits for `user.ready` before signing out and allows no console or socket error; that passed in the 6 runs after the change.

- **iOS and iPadOS home-screen Web Push:**
  - No device was available.
  - The "Add to Home Screen" hint was not rendered on a real iPhone.
- **Real mobile browsers:**
  - The phone layout was checked at 390×844 with touch emulation in all three engines.
  - The software keyboard covering inputs was not checked: emulation has no on-screen keyboard.
- **Not used:**
  - Sign-in providers (OIDC, Google, Microsoft): none are configured on the stack.
  - MCP integrations.
  - Signature-mode webhooks: they were offered in the UI; only URL-secret mode was posted to.
- **SMTP:** only plain SMTP to Mailpit. STARTTLS and TLS to a real relay were not exercised.

## 10. Release review and final verification

A code review of the whole v0.2.0 → v0.2.1 change came before the release commit.

**What was reviewed:**

- The six fixes, for correctness.
- The access and live-update paths:
  - MU-2 notices go to the person or the Team concerned and carry no data.
  - An `Access` notice only closes sockets; reopening one runs the normal access check.
  - MU-1 reads again only the Tickets of the Project whose socket connected, and only those on screen.
- UI side effects: `Dialog` still closes on its own Escape, close button and owner; the confirmation dialogs keep focus handling.
- Test coverage, complexity, and leftover or secret material. The only password in the change is the public end-to-end test password.

**What the review changed:**

- **MU-2 test coverage:** only the direct-role path was tested. The Team paths now have their own integration test (§3).
- **`client/apps/e2e/seed.sh`** (added in v0.2.0): on an empty stack it called `admin-cli bootstrap` without the required `--time-zone`, so the documented first run failed. It now passes `--time-zone "${E2E_TIME_ZONE:-UTC}"`, and like `seed-multi-user.sh` it takes `COMPOSE` for another Compose project. Both were used to seed the final stack.
- **Test assumptions that showed on a fresh database:**
  - `multi-user.spec.ts` expected the Workspace to be named "MU"; it now uses the Workspace's real name.
  - `support/test.ts` now treats WebKit's "… due to access control checks" page error within 2 s of a navigation as a cancelled fetch. `support/multiUser.ts` already did.
- **CHANGELOG:** the `## 0.2.0` heading, lost when the 0.2.1 notes were first added, was put back.

**Upgrade compatibility:**

- `git diff v0.2.0` touches nothing under `database/`, `docker/` or `server/.sqlx`: no migration, no Compose change, no new or changed setting.
